# 🎶 Adolfik — музичний Discord-бот для YouTube

Простий і сучасний музичний бот: тільки YouTube, тільки slash-команди, одна жива панель
«Зараз грає» з прогрес-баром і кнопками замість потоку повідомлень.

## Що вміє

- **/play** з автокомплітом: поки друкуєш, бот показує до 10 результатів YouTube (назва + тривалість).
  Можна вставити посилання на відео, Shorts або плейлист.
- **/search** — 5–10 результатів з мініатюрами, каналом і тривалістю + меню, де можна вибрати
  одразу кілька треків.
- Окрема черга для кожного сервера, повтор (вимк / трек / вся черга), shuffle, видалення з черги.
- Панель «Зараз грає» — картка на **Components V2** (як картка застосунку, а не embed): велика обкладинка,
  назва-посилання, канал, хто замовив, прогрес-бар `▶️ ▬▬▬🔘▬▬▬ 1:23 / 3:45` (оновлюється раз на 12 с),
  гучність, повтор, розмір черги і наступний трек. Смужка картки — у кольорі обкладинки. Бот редагує одне
  повідомлення, а якщо його засипало чатом — на новому треку переносить панель вниз.
- Керування прямо на картці: ⏸/▶️ пауза (праворуч від назви), ⏮ трек спочатку, ⏭ скіп, ⏹ стоп, 🔁 повтор,
  🔀 shuffle, 🔉/🔊 гучність і меню **«📜 Далі в черзі»** — до 25 наступних треків; вибери трек, і бот
  перейде на нього (треки перед ним прибираються; у режимі «вся черга» вони йдуть у кінець).
  Кнопки й меню persistent — відповідають і після перезапуску бота. Керувати можуть тільки ті, хто сидить
  у тому ж голосовому каналі, що й бот.
- Черга з пагінацією ◀ ▶ (по 10 треків) і загальною тривалістю.
- Помилки бачить тільки той, хто викликав команду (ephemeral).
- Автовихід: якщо в каналі нікого 2 хвилини (поки нікого — музика на паузі, хтось повернувся — грає далі)
  або черга порожня 5 хвилин.
- **Discord Activity** — плеєр у стилі музичного стрімінгу просто в голосовому каналі: пошук, обкладинки,
  черга з перетягуванням, керування для всіх у войсі (див. розділ «Discord Activity» нижче).

## Що потрібно

| Що | Навіщо |
|---|---|
| Windows 11, **Python 3.14** | [python.org](https://www.python.org/downloads/) (при встановленні постав галочку *Add to PATH*) |
| **Git** | `discord.py` ставиться останньою версією з GitHub — [git-scm.com](https://git-scm.com) |
| **Node.js** (LTS) або **Deno** | yt-dlp розв'язує ними JS-челенджі YouTube; Node.js також збирає фронтенд Activity — [nodejs.org](https://nodejs.org) |
| **ffmpeg** | лежить у `bin\ffmpeg.exe` (взятий з MusicBot). Якщо його нема — бот візьме `ffmpeg` з PATH |
| **cloudflared** (для Activity) | тунель, через який Discord відкриває Activity — `winget install --id Cloudflare.cloudflared` |

## 1. Створи бота в Discord Developer Portal

1. Відкрий <https://discord.com/developers/applications> → **New Application** → дай назву (наприклад, *Adolfik*).
2. Вкладка **Bot**:
   - **Reset Token** → скопіюй токен (показується один раз). Нікому його не давай.
   - **Privileged Gateway Intents** вмикати **не треба** — бот обходиться без них.
3. Вкладка **OAuth2 → URL Generator**:
   - *Scopes*: `bot` і `applications.commands`;
   - *Bot Permissions*:
     - **View Channels**
     - **Send Messages**
     - **Embed Links**
     - **Read Message History**
     - **Connect**
     - **Speak**
     - **Use Slash Commands** (у новому інтерфейсі — *Use Application Commands*)
   - Відкрий згенероване посилання і додай бота на свій сервер.

   Або просто запусти бота — готове посилання-запрошення з усіма правами з'явиться в консолі
   (рядок `Запросити бота: ...`). Код прав: `2150714368`.

## 2. Запуск

1. Двічі клікни **`start.bat`**. При першому запуску він:
   - створить віртуальне середовище `.venv` і поставить залежності з `requirements.txt`
     (далі ставить їх повторно, тільки коли `requirements.txt` змінився);
   - створить `.env` з `.env.example` і відкриє його в Блокноті.
2. Впиши в `.env` свій `DISCORD_TOKEN`, збережи і знову запусти `start.bat`.
3. У консолі мають з'явитися рядки на кшталт:
   ```
   Синхронізовано 13 slash-команд глобально: /play /search /queue ...
   Увійшов як Adolfik#1234 ...
   ```
   При наступних запусках, якщо набір команд не змінився, бот лише звіряє його з Discord
   («Slash-команди вже актуальні…») і не робить зайвої синхронізації — Discord обмежує часті
   глобальні оновлення. Синхронізація йде у фоні й ніколи не блокує старт бота.

Налаштування в `.env`:

| Змінна | Що робить |
|---|---|
| `DISCORD_TOKEN` | токен бота (обов'язково) |
| `DEFAULT_VOLUME` | гучність за замовчуванням, 0–150, типово `50` |
| `EMBED_COLOR` | колір embed-ів, наприклад `#8B5CF6` |
| `GUILD_ID` | необов'язково: ID сервера для **миттєвої** появи команд під час розробки |

> **Чому команди не з'являються?** Глобальна синхронізація (без `GUILD_ID`) може оновлюватися в
> Discord до години. Для розробки впиши `GUILD_ID` (ПКМ по серверу → *Копіювати ID сервера*; треба
> ввімкнути *Режим розробника* в налаштуваннях Discord → Розширені) — тоді команди з'являться одразу.
> Якщо колись синхронізував глобально, а потім додав `GUILD_ID`, команди можуть показуватися двічі —
> це нормально, глобальні дублікати зникнуть, коли знову запустиш без `GUILD_ID`.
> Після змін можна натиснути `Ctrl+R` у клієнті Discord.

Перевірка без постійного запуску: `.venv\Scripts\python bot.py --check` — бот залогіниться,
синхронізує команди, виведе список зареєстрованих команд і вийде.

## Команди

| Команда | Що робить |
|---|---|
| `/play <запит>` | назва (з підказками) або посилання на відео/плейлист YouTube |
| `/search <запит> [кількість]` | 5–10 результатів з мініатюрами, вибір одного чи кількох треків |
| `/queue [сторінка]` | черга з пагінацією |
| `/nowplaying` | перенести панель «Зараз грає» вниз чату |
| `/skip` | наступний трек |
| `/pause`, `/resume` | пауза / продовжити |
| `/stop` | зупинити і очистити чергу (бот лишається в каналі) |
| `/volume [рівень]` | гучність 0–150 %, без числа — показати поточну |
| `/loop [режим]` | вимк → трек → вся черга; без параметра — перемикає по колу |
| `/shuffle` | перемішати чергу |
| `/remove <позиція>` | прибрати трек з черги (є підказки з назвами) |
| `/leave` | вийти з голосового каналу |

Посилання `youtube.com/watch?v=…&list=…` додає **тільки це відео**. Щоб додати весь плейлист,
використовуй посилання виду `youtube.com/playlist?list=…` (до 500 треків за раз).

## cookies.txt — якщо YouTube пише «Sign in to confirm you're not a bot»

Іноді YouTube блокує запити з IP і просить увійти. Тоді:

1. Встанови розширення для експорту cookies у форматі **Netscape**, наприклад
   *Get cookies.txt LOCALLY* (Chrome/Edge) або *cookies.txt* (Firefox).
2. Увійди на <https://www.youtube.com> (краще окремим, не основним акаунтом), відкрий будь-яке відео
   і експортуй cookies для `youtube.com`.
3. Збережи файл як **`cookies.txt` поруч із `bot.py`** (у папці `Adolfik`). Перезапуск не потрібен —
   бот перевіряє файл при кожному запиті до YouTube.

`cookies.txt` — це фактично доступ до твого акаунта Google: нікому його не передавай. Він уже
доданий у `.gitignore`. Бот працює з копією файлу (`data\cookies\`), тож оригінал не перезаписується.
Те саме допомагає з відео з віковим обмеженням (потрібен акаунт 18+).

## Як це працює

- Звук **стримується**, а не качається: yt-dlp витягує пряме посилання на `bestaudio` (opus 128 kbps),
  ffmpeg читає його з `-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 5`.
- Посилання YouTube протухають, тому URL береться перед самим відтворенням: для першого треку —
  паралельно з підключенням до войсу, для наступного — під час поточного треку, щоб між треками не
  було тиші. Передзавантажений URL старший за 30 хв не використовується (самі посилання живуть ~6 год).
- YouTube тепер віддає аудіо тільки через ~5 с після запиту («передрол», до цього — `403 Forbidden`).
  yt-dlp повідомляє цей момент (`available_at`), і бот чекає його перед запуском ffmpeg.
- Якщо стрім обірвався посеред треку, бот один раз бере свіже посилання і продовжує з тієї ж секунди.
- Усі виклики yt-dlp ідуть у пулі потоків (`run_in_executor`) і не блокують бота. Пошук кешується
  на 15 хв, однакові запити, що летять одночасно, виконуються один раз.
- Автокомпліт: дебаунс 0,35 с (поки друкуєш, зайві запити відкидаються), відповідь не пізніше 3 с —
  якщо YouTube не встиг, результат доробиться у фоні і з'явиться на наступній літері.

## ⚠️ DAVE і davey

З березня 2026 Discord вимагає наскрізне шифрування голосу (DAVE). Для нього discord.py потрібен пакет
`davey`, і версія критична: **`davey>=0.1.7,<0.2`**. З davey 0.2.0 бот підключається до каналу
(зелене коло), але звуку **нема**. Обмеження прописане в `requirements.txt`, а бот при старті
перевіряє версію і не запуститься з невідповідною. Перевірити вручну:

```bat
.venv\Scripts\python -m pip show davey
```

Python 3.13+ не має модуля `audioop`; для гучності discord.py сам використовує пакет `audioop-lts`.

## Якщо щось не так

- **Бот у каналі, але тиша** — перевір версію davey (див. вище) і `logs\bot.log`.
- **`403 Forbidden` / «Sign in to confirm…»** — додай `cookies.txt`, онови yt-dlp:
  `.venv\Scripts\python -m pip install -U "yt-dlp[default]"`.
- **«No supported JavaScript runtime»** у лозі — встанови Node.js LTS або Deno і перезапусти бота.
- **`Не знайшов ffmpeg`** — поклади `ffmpeg.exe` у `bin\` або додай ffmpeg у PATH.
- Повний лог: `logs\bot.log` (ротація по 5 МБ, 3 файли).

## 🎶 Музичний канал (без команд)

1. Developer Portal → твій бот → **Bot** → **Privileged Gateway Intents** → увімкни **Message Content Intent** → Save.
2. На сервері виклич **/setup** (потрібне право «Керувати сервером»). Бот створить канал `🎶・музика`
   з постійною панеллю. Або вкажи наявний канал: `/setup канал:#music`.
3. Заходиш у войс і просто пишеш у цей канал назву пісні або посилання YouTube (можна плейлист).
   Бот вмикає трек, а твоє повідомлення прибирає. Керування — кнопками на панелі.

Боту в цьому каналі потрібне право **Manage Messages**, щоб прибирати повідомлення.
Вимкнути — **/unsetup** (канал залишиться). Налаштування зберігаються в `data/stations.json`.

## 🎧 Discord Activity — плеєр просто в голосовому каналі

Веб-інтерфейс у стилі музичного стрімінгу, що відкривається всередині Discord у войсі: пошук із підказками,
обкладинки, черга з перетягуванням, міні-плеєр. Звук, як і раніше, грає бот у войсі — Activity лише керує ним,
а стан наживо однаковий у всіх, хто її відкрив.

### Як це влаштовано

- **Бекенд** — у процесі бота (`webapi/`, aiohttp, той самий event loop, прямий доступ до плеєра). REST API +
  WebSocket `/api/ws`: повний стан при кожній зміні (трек, пауза, черга, гучність, повтор) і позиція раз на 1,5 с
  (між оновленнями фронтенд рахує її сам). Слухає тільки `127.0.0.1:WEB_PORT`.
- **Фронтенд** — `activity/` (Vite, React, TypeScript, Tailwind, Discord Embedded App SDK). Збірку `activity/dist`
  роздає той самий бекенд; `start.bat` перезбирає її сам, коли змінився код (потрібен Node.js).
- **Назовні** — тунель Cloudflare (`tunnel.bat`). Discord ходить до нього через свій проксі
  `https://<CLIENT_ID>.discordsays.com` за URL mappings.
- **Вхід** — SDK просить дозвіл (лише `identify`: ім'я й аватар) → бекенд обмінює код на токен через
  `DISCORD_CLIENT_SECRET` → видає свою підписану сесію на 12 годин.
- **Права як у кнопках панелі**: дивитися може будь-хто з сервера, керувати — тільки той, хто сидить у тому ж
  войсі, що й бот.

Без `DISCORD_CLIENT_SECRET` (і без `DEV_MODE`) веб-сервер не запускається — бот працює як звичайно.

### Налаштування (один раз)

1. Встанови cloudflared (після встановлення відкрий новий термінал):
   ```bat
   winget install --id Cloudflare.cloudflared
   ```
2. Developer Portal → твій застосунок → **OAuth2**:
   - *Client Secret* → **Reset Secret** → скопіюй (бот використовує лише токен, його це не зачепить);
   - *Redirects* → **Add Redirect** → `https://127.0.0.1` → **Save** (заглушка, якої вимагає Discord).
3. У `.env` бота:
   ```
   DISCORD_CLIENT_SECRET=<секрет із кроку 2>
   SESSION_SECRET=<довгий випадковий рядок>
   DEV_MODE=0
   ```
   `SESSION_SECRET` можна згенерувати: `.venv\Scripts\python -c "import secrets; print(secrets.token_urlsafe(32))"`.
   Без нього сесії скидатимуться при кожному перезапуску бота.
4. **Installation** → *Installation Contexts*: **Guild Install**.
5. **Activities → Settings**: увімкни Activities, у *Supported Platforms* відміть Desktop, Web, iOS і Android.
   Discord створить команду запуску «Launch» (Entry Point) — бот зберігає її під час синхронізації slash-команд.

### Запуск

1. **`start.bat`** — бот (і збірка фронтенду, якщо треба). У лозі має з'явитися
   `Activity: веб-сервер на http://127.0.0.1:8080 (фронтенд зібрано)`.
2. **`tunnel.bat`** — у вікні з'явиться адреса `https://xxxx.trycloudflare.com`.
3. Developer Portal → **Activities → URL Mappings**:

   | PREFIX | TARGET |
   |---|---|
   | `/` | `xxxx.trycloudflare.com` (адреса з кроку 2, без `https://`) |
   | `/ytimg` | `i.ytimg.com` (обкладинки YouTube) |
   | `/dcdn` | `cdn.discordapp.com` (аватари) |

   Безкоштовний тунель дає нову адресу при кожному запуску `tunnel.bat` — тоді онови рядок `/`.
   Для постійної адреси потрібен іменований тунель зі своїм доменом у Cloudflare.
4. У Discord: Налаштування → Розширені → **Режим розробника**. Зайди у войс → кнопка Activities (ракета) →
   **Adolfik**. При першому запуску дозволь доступ.

### Хто може запускати

Поки застосунок не верифікований Discord, Activity запускається **лише на серверах, де менше 25 учасників**, і
лише для розробників застосунку та запрошених **App Testers** (до 50; кожен вмикає *Application Test Mode* у
розширених налаштуваннях Discord). Для більших серверів потрібна верифікація застосунку.

### Керування

- **Бот сам у войс не заходить.** Поклич його кнопкою «Покликати бота» (вгорі або на Головній). Якщо бота нема у
  твоєму войсі, кнопки «грати» підписані «Покликати й грати» — одне натискання кличе бота й вмикає музику.
  `/play` і музичний канал працюють як раніше.
- **Сайдбар**: Головна, Пошук, Улюблені, Мої плейлисти і список плейлистів («+» — новий, 🗑 — видалити).
  На телефоні замість нього — нижня навігація.
- **Головна**: що грає на сервері, мої плейлисти, «Нещодавно на сервері» і «Продовжити слухати».
- **Таблиця треків**: ▶ при наведенні на номер (або подвійний клік), ❤ — в улюблені, «⋯» — грати зараз,
  наступним, у чергу, у плейлист, прибрати.
- **Плейлисти** (приватні, до 100, у кожному до 1000 треків): створити, перейменувати («Змінити»), видалити,
  перетягувати треки за ⋮⋮, імпорт YouTube-плейлиста за посиланням («Мої плейлисти → Імпорт з YouTube»).
- **❤ на панелі бота в Discord** теж додає трек в улюблені — Activity оновиться сама.
- **Плеєр унизу**: ❤, гучність, ⏮, ⏯, ⏭, повтор, перемішати, прогрес (клік — перемотати); кнопка праворуч
  відкриває панель «Зараз грає / Черга» (черга — перетягування, ✕ — прибрати, клік — перейти на трек).
- **Профіль** (аватар угорі праворуч або «Налаштування»): статистика і «Видалити мої дані».
- **Клавіші**: Пробіл — пауза/відтворення, `/` — до пошуку.
- Маленьке вікно Activity (картинка-в-картинці) — компактний плеєр.

Профілі, лайки й плейлисти зберігаються в `data/adolfik.db` (SQLite, створюється сама; у git не потрапляє).

### Розробка без Discord

1. У `.env`: `DEV_MODE=1` і `DEV_USER_ID=<твій Discord ID>` (ПКМ по собі → *Копіювати ID*).
2. `start.bat`, зайди у войс і відкрий у браузері <http://127.0.0.1:8080> (вибір сервера) або
   `http://127.0.0.1:8080/?guild=<id>`. `&user=<id>` — від імені іншого учасника.
3. Гаряче перезавантаження: при запущеному боті `cd activity`, `npm run dev` → <http://127.0.0.1:5173>
   (Vite проксує `/api` і WebSocket на бота).

> ⚠️ `DEV_MODE` вимикає вхід через Discord. **Ніколи не запускай його разом із тунелем.** Бекенд і так не приймає
> DEV-запити, що прийшли через тунель, але не покладайся на це.

### API

Усі запити — з заголовком `Authorization: Bearer <сесія>` (у `DEV_MODE` — `?user=<id>`).

| Метод | Шлях | Що робить |
|---|---|---|
| POST | `/api/token` | обмін OAuth2-коду з SDK на `access_token` і сесію |
| GET | `/api/state?guild=` | стан плеєра і права користувача (`you.can_control`) |
| GET | `/api/search?q=` | пошук YouTube (до 20 результатів, з кешем) |
| POST | `/api/play` | `{guild, query або url, mode: queue / next / now, summon?}` — без `summon` лише коли бот уже у твоєму войсі (інакше 409 `summon_required`) |
| POST | `/api/control` | `{guild, action, value?}`: pause, resume, toggle, skip, stop, previous_restart, seek, volume, loop, shuffle |
| POST | `/api/queue/move` · `/remove` · `/jump` | `{guild, index (from/to), id}` — індекси з 0; `id` рятує, якщо черга встигла зсунутись |
| POST | `/api/summon` | `{guild, channel_id}` — покликати бота у войс |
| GET/DELETE | `/api/me` | профіль і статистика / видалити свої дані |
| GET | `/api/me/likes` · `/likes/ids` · `/recent` | улюблені, їхні id, «продовжити слухати» |
| PUT/DELETE | `/api/me/likes/{video_id}` | лайк / зняти лайк |
| GET/POST | `/api/me/playlists` | список / створити `{name, video_ids?}` |
| POST | `/api/me/playlists/import` | `{url, name?}` — YouTube-плейлист у новий плейлист |
| GET/PATCH/DELETE | `/api/me/playlists/{id}` | плейлист з треками / перейменувати `{name}` / видалити |
| POST · DELETE | `/api/me/playlists/{id}/tracks` · `/tracks/{entry_id}` | додати `{video_ids}` / прибрати запис |
| POST | `/api/me/playlists/{id}/reorder` | `{entry_id, to}` |
| POST | `/api/me/likes/play` · `/api/me/playlists/{id}/play` | `{guild, mode, shuffle?, summon?}` |
| GET | `/api/history?guild=` | нещодавно на сервері |
| WS | `/api/ws?guild=` | перше повідомлення `{"type":"auth","session":"…"}`, далі сервер шле `state` і `position` |

### Якщо Activity не працює

- **Порожній екран або не відкривається** — чи запущені бот і `tunnel.bat`? Рядок `/` у URL Mappings — поточна
  адреса тунелю, без `https://`?
- **«Activity не налаштована»** — нема `DISCORD_CLIENT_SECRET` у `.env` (після зміни перезапусти бота).
- **«Discord не прийняв код авторизації»** — неправильний Client Secret.
- **«Discord не відповідає»** — закрий і знову відкрий Activity; `Ctrl+R` у клієнті Discord.
- **Нема обкладинок чи аватарів** — бракує mappings `/ytimg` і `/dcdn`.
- **«Сесія недійсна» після перезапуску бота** — задай `SESSION_SECRET`, тоді сесії переживуть перезапуск.
- **«Бота нема на цьому сервері»** — запроси бота (посилання-запрошення друкується в лозі при старті).
- **У лозі «не вдалося запустити веб-сервер … Порт зайнятий?»** — зміни `WEB_PORT` і перезапусти `tunnel.bat`.
- **Activity нема в списку** — Activities увімкнені? На сервері менше 25 учасників? Ти розробник або App Tester?
  Режим розробника увімкнено?
